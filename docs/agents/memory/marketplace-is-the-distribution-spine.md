Since `eb73194`/`50107c4` (2026-08-31) the repo doubles as a private Claude plugin marketplace:
`.claude-plugin/marketplace.json` at root, payload at `marketplace/aac-skills/` (ONE plugin, `aac-skills`, 53 skills: the ~/.claude/skills set merged with the hand-edited repo `aac-skills/` team tree — Dan chose one giant package over a split, 2026-08-31 evening), both regenerated by
`tools/build-cloud-plugin.py`, run on a branch after any `aac-skills/` edit (issue 214 retired the
push that used to run it). Merging that branch to master IS the whole publish flow.

Consumers, all verified live that day:

- Claude Code CLI + Code Desktop: `aac-skills@claude-dotfiles` installed at user scope on both
  profiles (earlier `dan-skills` names uninstalled).
- claude.ai personal plugins, both accounts: Settings > Plugins > Add > "Add from a repository" —
  the product accepts a private GitHub repo there even though the help-center docs only describe
  zip upload. Docs lag product; trust the UI screenshot over the article.
- AAC org-wide: admin plugins page, same GitHub-synced add. First add showed a BLANK plugin list;
  fixed by making the version valid semver (`2026.8.31`, not `2026.08.31` — leading-zero segments
  are invalid and the org parser drops the plugin silently where `claude plugin validate` only
  warns) and re-adding the marketplace. Update alone was not confirmed sufficient — Dan removed
  and re-added.

**How to apply:** never emit a date-based version with zero-padded segments into any plugin or
marketplace manifest. When an org marketplace lists zero plugins, check semver validity and Claude
GitHub App repo access before anything else. The zip build (`dist/dan-skills.zip`) survives only
for claude.ai Skills pages (Customize > Skills, admin-settings > Skills), which remain upload-only.
