- Pre-commit hooks (and any git subprocess) leak GIT_DIR / GIT_INDEX_FILE / GIT_WORK_TREE / GIT_COMMON_DIR / GIT_OBJECT_DIRECTORY into every child process. These env vars override `git -C <path>` completely, so any script that spawns git against a path OTHER than the parent repo silently operates on the parent instead. This class of bug hit the new freshness tests intermittently (fixed inline). Other scripts in the repo that spawn git against arbitrary paths from a hook or test context - sync.ps1, tools/tracker-audit.js, tests/restore-test.ps1's own git calls - could hit the same bug. Systematic fix: any git-invoking helper that takes an explicit path should clear those env vars first, or the pre-commit hook itself should clear them before invoking children. The pattern is now in tools/dotfiles-freshness.ps1's Invoke-Git.
